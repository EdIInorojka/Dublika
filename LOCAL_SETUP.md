# Дублика — локальный MVP

Рабочая версия запускается на этом компьютере и слушает только `127.0.0.1`. Исходники, записи и готовые ролики остаются в папке `.local-data` и не отправляются на публичный сайт.

## Первый запуск

```powershell
npm install
npm run setup:media
npm run local
```

После запуска откройте [http://localhost:8788](http://localhost:8788).

Встроенная демо-сцена создаётся сервером локально: она не зависит от YouTube,
VK или внешнего CDN и годится для проверки всех четырёх шагов студии.

Для теста с другого компьютера одного Vercel недостаточно: браузер другого
человека не может обратиться к `127.0.0.1` вашего ПК. Нужен публичный HTTPS
адрес для медиасервера (например, именованный Cloudflare Tunnel или отдельный
сервер с GPU/CPU-воркерами). Укажите его при сборке фронтенда как
`VITE_API_ORIGIN`, а домен Vercel разрешите на сервере:

```powershell
$env:DUBLIKA_ALLOWED_ORIGINS = 'https://адрес-деплоя.vercel.app'
$env:VITE_API_ORIGIN = 'https://api.example.ru'
$env:DUBLIKA_PUBLIC_ORIGIN = 'https://адрес-деплоя.vercel.app'
$env:DUBLIKA_HOST = '0.0.0.0'
$env:DUBLIKA_MAX_CONCURRENT_RENDERS = '2'
$env:DUBLIKA_DEMUCS_DEVICE = 'cuda' # только если на сервере есть CUDA
npm run local
```

Для реального запуска используйте постоянный домен API, а не временный
`trycloudflare.com`: его адрес меняется после перезапуска и приводит к
`Failed to fetch` у других пользователей.

## Запуск production-сервера

В репозитории есть контейнер, который сам собирает фронтенд, устанавливает
Demucs для отделения оригинального голоса и сохраняет пользовательские файлы
в `./data`. На сервере с Docker:

```bash
cp .env.example .env
# заполните в .env реальные домены и секреты, описанные ниже
docker compose up --build -d
```

Откройте порт только на `127.0.0.1:8788` и поставьте перед ним HTTPS reverse
proxy. Для GPU-воркера укажите `DUBLIKA_DEMUCS_DEVICE=cuda` и используйте
образ/host с NVIDIA Container Toolkit. Для CPU оставьте значение `cpu`.

## Перед публичным запуском

1. Поставьте API за HTTPS reverse proxy (Caddy, Nginx или Cloudflare Tunnel) и
   оставьте доступ к Node-порту только из локальной сети прокси.
2. Укажите `VITE_API_ORIGIN` при сборке фронтенда и тот же публичный домен в
   `DUBLIKA_ALLOWED_ORIGINS`; иначе браузер другого пользователя не сможет
   отправить файл или запись микрофона.
3. Добавьте `DEEPGRAM_API_KEY`, `RESEND_API_KEY` и `OTP_FROM_EMAIL` в секреты
   сервера. Они не должны попадать во фронтенд или Git.
4. Для сервера с NVIDIA GPU задайте `DUBLIKA_DEMUCS_DEVICE=cuda`; без GPU
   оставьте `cpu`. Число тяжёлых рендеров ограничивается
   `DUBLIKA_MAX_CONCURRENT_RENDERS`, поэтому пиковая нагрузка не ломает уже
   выполняющиеся заказы.
5. Тестовый realm разрешайте только на локальной машине через
   `DUBLIKA_ENABLE_QA=1`. В публичном режиме API создаёт проекты только для
   пользователя с подтверждённым почтовым входом.
6. Для входа через Google, Яндекс, GitHub или LinkedIn задайте пару
   `OAUTH_<ПРОВАЙДЕР>_CLIENT_ID` / `OAUTH_<ПРОВАЙДЕР>_CLIENT_SECRET` и
   `DUBLIKA_API_ORIGIN`. В консоли провайдера зарегистрируйте callback
   `https://ваш-api-домен/api/auth/oauth/<provider>/callback`. Кнопка появится
   в интерфейсе только после того, как соответствующие секреты действительно
   настроены. Для VK ID адреса OAuth задаются отдельными `OAUTH_VK_*_URL`,
   чтобы использовать текущую схему зарегистрированного VK-приложения.

## Что уже работает

- загрузка MP4, MOV, WebM, MKV и M4V размером до 1 ГБ;
- импорт прямой ссылки, YouTube и VK Видео;
- выбор фрагмента продолжительностью до 4 минут;
- разбиение речи на целые предложения и естественные паузы (обычно 2–4 секунды, до 8 секунд для неразрывной фразы);
- запись микрофона по репликам с живым индикатором громкости и транскрипцией;
- одна секунда входа и выхода для записи, затем автоматическая остановка; финальный рендер сохраняет эту синхронизацию;
- управляемое прослушивание без одновременного запуска нескольких отрывков;
- очистка и нормализация голоса, приглушение исходной дорожки под дублем;
- сборка H.264/AAC MP4 без вшитых субтитров;
- вход по коду и три пробных рендера на подтверждённый профиль; локальный QA
  отделён от пользовательской базы и недоступен извне.

## Автоматическое распознавание текста

Для автоматической расшифровки нужен ключ Deepgram: сервер передаёт только
выделенный пользователем фрагмент в Deepgram Nova-3 Multilingual, получает
таймкоды слов и смысловые фразы, затем собирает из них целые предложения и
естественные паузы. В запросе включены `smart_format`, `utterances` и отказ от
Model Improvement Program. Без ключа приложение **не выдумывает субтитры**:
оно создаёт пустые таймированные окна по реальной звуковой дорожке, в которые
можно вписать сценарий вручную.

```powershell
$env:DEEPGRAM_API_KEY = 'ваш_ключ'
npm run local
```

## Платежи и учётные записи

Тарифы создают настоящий redirect-платёж ЮKassa только при наличии
`YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY` и `DUBLIKA_PUBLIC_ORIGIN` (HTTPS).
После оплаты доступ выдаётся исключительно после сверки webhook с API ЮKassa,
а не по возврату пользователя на сайт. В кабинете ЮKassa добавьте webhook
`payment.succeeded` на `https://ваш-api-домен/api/billing/yookassa`.

Telegram/OAuth требуют зарегистрированных приложений и их секретов. Почтовый
вход в production использует `RESEND_API_KEY` и `OTP_FROM_EMAIL`; без них
внешний OTP намеренно не выдаётся в интерфейсе. Публичный доступ к этому
компьютеру следует открывать только через HTTPS-прокси; Node-медиасервер не
должен быть напрямую доступен из интернета.
